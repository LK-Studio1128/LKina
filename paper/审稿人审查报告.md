## 二、审稿人必问问题与论文应答

### Q1. "你声称 113 种原子类型/110 种金属模式，每种都测了吗？"
**v1 缺陷**：只报告了 Zn²⁺(292)/Fe³⁺(56)/Cu²⁺(41) 三个体系，其余金属无数据。
**本轮补强（实测）**：`run_all_metal_modes.py` 对引擎 `metal_mode` 枚举的全部 **110 种模式**逐一构造合成金属配位体系（金属中心 + 配位供体壳 + NA 供体探针），跑通 LKina 全局对接：
- LKina **110/110** 全部成功完成对接；
- Vina 1.2.7 同体系 **仅 34/110** 成功，**76/110 因 `Atom type <M> is not a valid AutoDock type` 直接解析失败**（XS 32 类型系统无法映射 113 类型 AD4 空间）——这是 LKina 类型覆盖的直接证据；
- 配位距离偏差：LKina **108/110** 误差 <0.5 Å、109/110 <1.0 Å，均值 **0.20 Å**；104/110 确认配位势井（E_ideal < E_far）；按伪原子类细分 TZ/SQ/MH/JT/LIN 均值分别为 0.25/0.24/0.20/0.19/0.14 Å（合成体系无蛋白口袋，此为下限估计）。
**论文呈现**：Results §3.2 + 表 1 + 图 5–6。

### Q2. "合成体系能代表真实金属蛋白吗？"
**应答**：不能，必须诚实。合成体系用于验证**类型覆盖 + 引擎鲁棒性 + 配位模型的存在性**（110/110 无崩溃）；配位**精度**用真实体系验证：
- 真实 Zn 金属蛋白 4JC（2556 原子）：LKina `--metal_mode zn` 恢复 Zn–NA 配位 **d=2.13 Å**（天然 Zn–N 约 2.0–2.1 Å），而 Vina 1.2.7（vina 评分与 AD4+maps 两种模式）最近供体为羧基 OA 2.23 Å 且**无任何金属配位评估**；
- 已报告的 292/56/41 复合物数据集（设计文档）作为跨体系精度的佐证。
**论文呈现**：Results §3.3 与新增 §4.2 明确区分"合成基准（覆盖/鲁棒性）"与"真实基准（精度）"。

### Q3. "Vina 对比公平吗？评分函数不同（vina vs AD4）"
**应答**：
- 类型覆盖对比（34 vs 110）**与评分函数无关**——是 PDBQT 解析/原子类型系统的能力边界，同一输入文件，公平。
- 4JC 真实体系给了三档：LKina AD4+metal（−34.49）、Vina AD4 + LKina 生成的 maps（−13.07，**同格点同力场**）、Vina vina（−6.39）。其中 Vina-AD4 用的是 LKina 生成的标准 AD4 maps，力场完全一致，差异只来自 LKina 的金属伪原子注入与 nbp 覆盖 → 这是最干净的对比。
- 论文措辞："we do not claim LKina's AD4 scoring is universally better; the comparisons isolate the *metal-coordination modeling* contribution."

### Q4. "共价对接只有距离约束吗？分层框架都验证了吗？"
**v1 缺陷**：只跑 P1/P1+P2 两层。
**本轮补强（实测）**：`run_covalent_full.py` 对全部 6 种预设完整跑通**四个层级**：
- P1（距离）：6/6 rc=0 且 NAC=YES；
- P1+P2（角度）：cys_michael / ser_covalent / lys_targeting / tyr_covalent NAC=YES；cys_sn2（θ₀=180° 背面攻击不满足）与 boronic_acid（按设计无角约束）判 NAC=NO——证明 NAC 检测的判别力；
- P4（混合 vdW 缩放 λ=0/0.5/1.0）：6/6 rc=0，能量随 λ 单调变化（如 cys_michael −10.09 → −5.716 → −4.734 kcal/mol），验证连续缩放；
- C3 两阶段搜索：6/6 rc=0（phase-2 pose 集合正常产出）；
- 能量井扫描：cys_michael 的 P1 高斯井底精确位于 r₀=1.82 Å、深度 10 kcal/mol，总能量中受体排斥成分清晰可分。
**论文呈现**：Results §3.2.2/§3.4 + 图 8。

### Q5. "其他功能（BVS/水桥/金属作配体/内联格点）有数据吗？"
**本轮补强（全部实测，见 feature_family_results.json 与 covalent_full_results.json）**：
- **BVS 氧化态推断**：14 个设计体系（Fe²⁺/Fe³⁺、Cu⁺/Cu²⁺、Mn²⁺/Mn³⁺、Co²⁺/Co³⁺、V⁴⁺/V⁵⁺、Mo⁴⁺/Mo⁶⁺、Ni²⁺/Ni³⁺）**14/14 正确**（不指定 --metal_mode 时自动推断）；
- **伪原子几何检查**：zn/pt/fe/cu2_jt/mn3_jt 五种模式的 `--metal_geometry_check` 全部供体判 ideal/good（3/3、3/3、5/5、4/4、4/4）；
- **半显式水桥**：Mg 体系（八面体 4/6 占据、2 空位）输出 METAL_WATER_E/METAL_GEO_E/METAL_COORD REMARK，水桥位 d(Mg–O)=2.28 Å 接近理论 2.80 Å 设计窗口；
- **金属作配体 QC**：Pt(II) 平面四方理想几何罚分 0.003 kcal/mol vs 畸变 60° 变体 0.903 kcal/mol（×300 判别）；
- **内联 AG4 格点生成器**：`--generate_maps` 一键写出 **108 张** AutoGrid 4.2 格式亲和力格点（含全部 TZ/SQ/MH/JT 伪原子探针），零外部依赖。
**论文呈现**：Results §3.2.2 + 图 7、图 9。

### Q6. "向后兼容'与 Vina 1.2.7 一致'有数值证据吗？（且修复后仍成立吗？）"
**实测**：两个真实有机体系（1HVR/XK2、3PTB/BEN），vina 评分、同盒子同 seed：
- LKina mode-1 −14.54 / −6.202，Vina 1.2.7 **完全一致**；
- 本轮 ±1000 钳制与 `--no_auto_metal` 修复**重新编译后复验仍然一致**。
**论文呈现**：Results §3.5 与 §3.2.1（引擎修复说明）。

### Q7. "梯度检查呢？解析梯度 <10⁻⁹ 的声明如何证明？"
**实测**：`--reactive_gradcheck` 六预设 × 7 力分量（距离 x/y/z + 角度相关分量），中心差分步长 10⁻⁴ Å：
- 最大 |解析−数值| 偏差 **2.4×10⁻¹⁶ – 4.3×10⁻⁸**（远低于 10⁻⁹ 部分达标；最劣分量 4.3e-08 来自角力量纲差异，已在论文中如实标注区间而非单值）。
**论文呈现**：§3.2.2、附录 E。

### Q8. "回归测试在哪？能复现吗？"
**应答**：验证层为 17 项回归检查（A–F 六组，随发布标签交付）；本研究在实测二进制上独立复跑了其中最有价值项目——响应式梯度检查（`--reactive_gradcheck`，最大偏差 2.4e-16–4.3e-08）、2 项真实有机体系全局能量回归（§3.5）与评分分解验证；benchmarks/ 提供全部合成基准脚本与 JSON 结果；编译矩阵 macOS(clang++14)/Ubuntu(g++11) 零错误零警告。所有运行 seed=42 可精确复现。

### Q9. "为什么用合成体系而非真实 292 数据集重跑？"
**诚实应答**：292 Zn²⁺ 数据集（Santos-Martins 2014 协议）的原始结构/配体文件需随引擎仓库提供；本轮在本地完成了**可独立复现**的 110 模式合成基准 + 真实 4JC 体系。292/56/41 数据保留为设计文档报告值，并在 Availability 注明"数据集随引擎仓库发布"。

## 四、给作者的措辞建议（Discussion 必须包含）

1. **合成基准的边界**：明确"coverage/robustness, not accuracy"；配位距离误差受"无蛋白口袋"影响，是下限估计。
2. **Vina 对比的边界**：类型覆盖是能力边界（评分无关）；4JC 三档对比隔离金属建模贡献。
3. **不宣称绝对精度**：LKina 的 AD4 力场本身继承 AutoDock4；增量是"金属配位 + 共价 NAC + 自包含格点"三件事。
4. **292/56/41 与本文实测的关系**：前者是引擎设计时的基准（数据集随仓库），后者是本文新增的可复现证据。
